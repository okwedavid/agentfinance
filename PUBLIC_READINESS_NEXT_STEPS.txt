PRODUCTION READINESS
---------------------
STATUS: NOT PUBLIC READY.
Category: Functional but requires significant fixes.

The deployment, CORS, auth, WebSocket and the frontend build all work.
The core product (AI agent task execution) is BROKEN in production, and
there is a CRITICAL treasury-drain vulnerability in the payout flow.
Several endpoints expose all users' data without authentication.

--------------------------------------------------------------------
CRITICAL BLOCKERS (resolve before any public launch)
--------------------------------------------------------------------
1. [BLOCKER - FINANCIAL] Unprotected payout approval
   - Any registered user can prepare + approve a payout that broadcasts
     real funds from the live EVM treasury (signer is ready and live).
   - Files: backend/src/services/payoutService.js:328-381
            backend/src/index.js:648-656
            frontend/src/app/wallet/page.tsx:236-247

     approvalToken, add hard amount caps + limits, remove
     TREASURY_PRIVATE_KEY from the environment until fixed.

2. [BLOCKER - PRODUCT] AI agents completely broken
   - Live test failed on ALL 7 providers:
     Groq 401 (invalid key) | Google 404 (gemini-2.0-flash retired) |
     Anthropic 400 (credit) | Mistral 429 | Cerebras 404 |
     OpenRouter/Together (unset).
   - Files: backend/src/agents/agentRunner.js
   - Fix: use a working provider first (fix Groq key / update to a
     current Gemini model), add a research-engine fallback so tasks
     still complete without an LLM, add a per-task global timeout.

3. [BLOCKER - DATA] Unauthenticated analytics endpoints
   - /analytics/summary, /analytics/history, DELETE /analytics/clear
     return 200 without auth and leak ALL users' tasks, wallets and
     payouts; the clear endpoint archives every user's tasks.
   - File: backend/src/routes/analytics.js
   - Fix: require JWT, scope queries to req.user.sub.
